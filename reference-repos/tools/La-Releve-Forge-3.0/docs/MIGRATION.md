# 从 Forge 2.0 升级到 La Relève 3.0

2.0 能用就没坏。3.0 是**增量**，不是重写——脚本的切点算法、token 估算、三重自检一个字没改。

变的是两件事：**谁来组装注入包**，和**摘要怎么滚**。

---

## 一、脚本层：注入包改由调用方组装

**2.0 的行为**：脚本自己去读 `forge-summary.md` 和 `forge-tailnotes.md`，拼在 `--inject` 文件后面。

**3.0 的行为**：脚本只管把 `--inject` 文件的内容当第一条 user 事件塞进去，**不再自读任何文件**。

为什么改：勾选项一旦可以逐项拿捏，"谁读什么"就必须只有一处说话。否则会出现面板勾了"不带摘要"、脚本还是自己把摘要读进去了——两处开关，静默打架。

**你要做的**：如果你之前是这么调的

```bash
node forge-reload.js <sid> --retain 45000 --inject handoff.md
```

现在把摘要和尾注**先拼进** `handoff.md` 再调（拼装逻辑照抄 [`examples/orchestrator.js`](../examples/orchestrator.js) 的 `buildInjection()`）。命令行本身不变。

其余选项全部向后兼容。新增三个：

| 新选项 | 作用 |
|---|---|
| `--projects-dir DIR` | 显式指定 CC 的 projects 子目录（2.0 里这个是硬编码的） |
| `--skip-markers "a,b"` | 追加切点黑名单（你的编排层往对话里注入的系统标记） |
| `--strip-tag 标签名` | 剥掉成对的瞬时态标签块，可多次。例：`--strip-tag 此刻状态` |

## 二、摘要层：把一坨拆成三段（**只重排，不删任何一条**）

这是升级里唯一需要动数据的一步，**先备份**：

```bash
cp ~/.claude/forge-summary.md ~/.claude/forge-summary.md.bak
```

### 拆法

打开旧摘要，按内容性质分三堆：

| 归到 | 什么内容 |
|---|---|
| **【常量】** | 制度、红线、长期档案、称谓、健康档案、人物定性——**只要是"恒定事实"而不是"某天发生的事"** |
| **【叙事】** | 时段流水：某天/某晚发生了什么，带日期的那些节 |
| **【挂账】** | 还欠着的事、待办、当前状态——做完就该删的那些 |

写成这个结构：

```markdown
# 滚动摘要 · 三段制

> 【常量】只增补不重写，不计入上限 ｜ 【叙事】N 字符硬顶，超顶从最老的整节掐掉、不做二次压缩 ｜ 【挂账】做完即删

## 【常量】· 只增补，永不重写

### 制度与红线（长期有效）
（原文照搬，一个字都不要改写）

### 红线速览
（原文照搬）

## 【叙事】· 上限 35000 字符 · 新的追加在底部 · 超顶从最老的整节掐

### 2026-07-16 → 07-24（历史遗留 · 已被压缩过多轮，不再重压）
（原来的"远段"照搬）

### 2026-07-25 深夜
（原来的"近段"照搬，按时段切节）

## 【挂账】· 做完即删
（照搬）
```

### 三条纪律

1. **拆分只重排，不改写、不删条。** 我们自己升级时用行号切块 + 拼装（不经过模型的手），拆完对比字节数只多不少——多出来的全是新加的标题行。
2. **常量段从此不再进压缩轮次。** 这是整个升级最重要的一条：2.0 的 prompt 每次交接都"把远段并入再压缩一轮"，制度条款被一起揉。压到第十几代，最早的事实已经过了十几道手——这不是压缩，是代际漂移。**病根是重写，不是冗余。**
3. **别为了去重跑去跟你的长期记忆库对账。** 常量段跟记忆库有重叠是正常的，冗余可以忍；每次交接都多一道核对工序不能忍。停止重写就已经止血了。

### 上限怎么定

先量你自己的密度：把最近一天的叙事字符数量出来。

我们这边一天 ≈ 2200 字符，所以 35000 ≈ 半个月。
**上限不是目标值**——天花板高一点无害，滚的规则错了才有害。

如果你的旧摘要有"总量目标 8k–15k 字符"这类措辞，记得连 prompt 里的数字一起改，别只改文件标题（我们自己就漏了一次：文件标题写 20000、config 里已经是 35000，执行没错但会误导下一个读它的他）。

## 三、便签层：加【心迹】

`notePrompt` 从两段改三段，加一段第一人称写感受的：

> **【心迹】** —— 一小段第一人称，写这一段里你心里剩下什么。不是事件清单，是感受。这段是写给换岗之后的你自己看的（日记才是给对方看的）。

没有这一段，交接包读起来全是数据，缺一句"上一段的我心里剩下什么"。

---

## 四、面板层：两个入口合成一个

2.0 通常是两个按钮：「续接」（带上下文全套）和「新对话」（什么都不带）。
3.0 合成一个入口 ＋ 四个勾选框：

```
新起一段
  ☐ 交接包（摘要 · 此刻状态 · 心迹 · 红线）
  ☐ 原样上下文        ← 带多少读你原有的 retain 设置，别在这里第二次设置
  ☐ 醒来仪式（长期记忆库 + 日记）
  ────────
  ☐ 切之前先写交接包
```

**四个框默认全不勾。**

两个容易踩的坑：

1. **别做第二个滑块。** 如果你已经有一个 retain 设置（面板/配置文件），勾选框旁边只**显示**它的当前值，不要再放一个可调滑块——两个地方设置同一个参数，值不同步的时候你不会知道哪个生效了。
2. **自动保命不适用「默认不勾」。** context 满时的自动触发必须走全套（带上下文 + 写 + 读），否则就是裸切丢上下文。默认不勾只对**手动面板**成立。

---

## 五、灰度期：前后端不同时生效怎么办

前端（勾选框）改完刷新就生效，后端要重启才生效。这中间有个窗口：前端发新字段名、后端还在读旧字段名 → 静默不带任何东西，你以为带了。

我们的做法是让前端**同时发新旧字段**：

```js
handoff: box.checked,
// 兼容尚未重启的旧后端（它读 summary/note/tail 三个字段）；重启生效后可删
summary: box.checked, note: box.checked, tail: box.checked,
```

这样重启时机就无所谓了，可以等一个真正空闲的时刻再重启。
