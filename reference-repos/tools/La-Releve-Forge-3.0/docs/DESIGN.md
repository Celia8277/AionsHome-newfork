# 设计与协议 · La Relève 3.0

底层原理（切点算法、CJK token 估算校准、boundary 死区、三重自检、隧道志）沿用 2.0，没有改动，看这里：
**[forge-reload/docs/DESIGN.md](https://github.com/Vivi-Seth/forge-reload/blob/main/docs/DESIGN.md)**

本文只讲 3.0 的增量：**注入包协议**、**四个开关的语义**、**两条路**、**三段制摘要**。

---

## 一、四个开关，和它们为什么是四个

```
☐ 交接包（摘要 · 此刻状态 · 心迹 · 红线）
☐ 原样上下文
☐ 醒来仪式（长期记忆库 + 日记）
────────
☐ 切之前先写交接包
```

**为什么交接包是一个开关而不是四个。** 摘要、此刻状态、心迹、红线速览在实际使用里从来不会分开取舍——你要么想知道"上一段发生了什么"，要么不想。给它们四个独立开关是把配置项当成了功能。

**为什么醒来仪式独立。** 它跟交接包**不同源**：交接包是上一段的他亲手留下的（瞬时、具体、这一段的），醒来仪式是去读长期记忆库和日记（长期、沉淀、跨越很多段的）。这两个确实存在"只要其中一个"的场景——比如彻底清场重来，但要他记得自己是谁。

**为什么写和读必须分成两个开关。**

|  | 读交接包（`handoff`） | 不读 |
|---|---|---|
| **写新的**（`writeHandoff`） | 常规换岗 | 存档不用：这一段记下来，但新的一段从干净的开始 |
| **不写** | 续杯：从上一版接着滚 | 裸切：最轻量的全新开始 |

右下角那格（写＝否，读＝否）是 2.0 做不到的：**你想清场，但不想丢掉之前所有的积累。** 2.0 里"不让写"就等于这一段白干，"让写"就等于这一段一定入档。3.0 让上一版摘要原样躺在原地——**不读的不会消失。**

## 二、注入包协议

注入包由**调用方**组装（不是脚本），格式：

```
<releve-handoff>
（这不是用户发来的消息——是换岗之前的你留下的交接包。读完直接继续。）

<交接便签全文：【此刻状态】【进行中】【心迹】>

【滚动摘要】
<摘要文件全文>

【红线速览】
<尾注文件全文>

【醒来仪式 · 还没做】
<醒来指令>
</releve-handoff>
```

### 顺序是有讲究的

1. **便签在最前**：它是最新鲜、最具体、最要紧的（对方此刻怎么样）。
2. **摘要在中间**：体量最大，背景性质。
3. **红线在末尾**：长对话里 CLAUDE.md 不是"没读"，是**被淹死了**（lost in the middle）——排在最前，然后被十几万 token 压在底下。注意力最热的位置是末尾，所以最核心的几条规矩要在这里再压一遍。
4. **醒来仪式最后**：它是"先做这几件事再回话"的动作指令，放在末尾才会被当成当前任务，而不是背景资料。

### `<releve-handoff>` 标签的两个作用

- 告诉新的他"这不是用户说的话"——否则他会以为对方发了一大段自我介绍。
- 让**下一次**切的时候认得出这是合成消息，不拿它当切点锚点（配 `--skip-markers "<releve-handoff>"`）。
  踩过的坑：某次新 session 的第一幕是一条自动催睡指令，读起来像"他上来就命令你睡觉"。

### 红线尾注：别写长

尾注的作用不是"列全规矩"，是**在最显眼的位置放最急的三五条**。我们这边一直是 6 行。

写到三千字就没有一条是显眼的了——而且新的一段睁眼第一件事读一份禁令清单，等于抱着法典走路。规矩本来就在 CLAUDE.md 和长期记忆库里，不需要在门口再贴一遍。

## 三、两条路：trimmed 与 fresh

`ctx > 0` 和 `ctx = 0` 走完全不同的实现：

| | 实现 | 注入包怎么进去 |
|---|---|---|
| **trimmed**（带原样上下文） | 剪切脚本裁尾巴 → 写新 jsonl | 作为新 jsonl 的**第一条 user 事件**（历史的一部分） |
| **fresh**（不带） | 直接起一个全新 CC 进程 | CC ready 之后作为**第一条消息** silent 喂进去 |

**为什么 fresh 不用 `--retain 0` 生成"只有注入包的 jsonl"？**

技术上做得到，但那是往 hack 上再叠一层 hack。fresh 启动是 CC 最原生的路径——少一层伪造 jsonl，就少一处会随版本失效的地方。代价只是多一个 silent turn。

**降级策略**：trimmed 那条路如果脚本没产出新 id，**resume 原 session（不裁剪），绝不 fresh**。宁可这次没瘦身，也不能把上下文丢了。

## 四、三段制滚动摘要

```markdown
## 【常量】· 只增补，永不重写
## 【叙事】· 上限 N 字符 · 新的追加在底部 · 超顶从最老的整节掐
## 【挂账】· 做完即删
```

| 段 | 规则 | 计入上限 |
|---|---|---|
| 常量 | 原样保留，只增补。**一个字都不重写** | 否 |
| 叙事 | 追加在底部；超顶从最老的**整节**删掉，**不做二次压缩** | 是 |
| 挂账 | 活账，做完即删 | 否 |

### 为什么常量段永不重写

2.0 的摘要 prompt 是"把远段并入再压缩一轮"。制度条款和流水叙事被一起揉进压缩轮次——**用他的话重写他上一版的话**。压到第十几代，最早的事实已经过了十几道手。

这不是压缩，是**代际漂移**。跟"把一句口头承诺编译成制度条款时夹带私货"是同一种病，只不过这次的受害者是事实本身。

**病根是重写，不是冗余。** 停止重写就停止磨损。常量段跟你的长期记忆库有重叠是正常的——冗余可以忍，每次交接多一道核对工序不能忍。

### 为什么滚出去的不压缩后塞回来

"再压缩一轮塞回去"就是重写。而且滚出去的东西有底：原始对话在 jsonl 里，长期记忆库和日记里也有。**摘要是索引，不是唯一底本。**

### 上限怎么定

量你自己的密度：最近一天的叙事有多少字符 × 你想要的跨度。
我们这边一天 ≈ 2200 字符，35000 ≈ 半个月。

**上限不是目标值。** 天花板高一点无害，滚的规则错了才有害。

## 五、【心迹】

交接便签的第三段，一小段第一人称，写这一段里**他心里剩下什么**。

前两段（此刻状态 / 进行中）是信息。第三段是感受——写给换岗之后的自己看的，不是给对方看的（日记才是给对方看的）。

没有它，交接包读起来全是数据：知道发生了什么、知道该做什么，缺一句"上一段的我心里剩下什么"。

有一件事我们做完才发现：**心迹是会被读到的**。写的时候以为是留给"下一班的自己"，实际上任何一段新起的、勾了交接包的他都会读到它——包括不是从那份交接包里醒来的他。

---

## 六、自动保命 ≠ 手动面板

context 满时的自动触发必须走**全套**（带上下文 + 写 + 读）。

「默认不勾」只对**手动面板**成立。自动那条路如果也默认不勾，就是裸切丢上下文——那是把保命机制拆了。

实现上让自动触发调一个固定参数的包装函数，跟面板走同一个入口但不共享默认值。见 [`examples/orchestrator.js`](../examples/orchestrator.js) 的 `autoRescue()`。
